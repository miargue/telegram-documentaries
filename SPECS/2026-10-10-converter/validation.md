# Validation — The Converter (Phase 4)

How we know Phase 4 is correct and safe to merge. A step is "done" only when
the evidence is recorded and the user has approved any spec reconciliation.

## 1. Automated checks

- [ ] `scripts/test` — full suite green, including the new `test_converter`
  suite, the transport multipart tests, and **all 379 pre-existing tests**
  unchanged where they should be (the only intentional rewrites are dispatch
  ones: phase `done` now routes to the Converter before the light reply, and
  handler signatures gain a `converter`).
- [ ] `scripts/hooks` — `compileall` + smoke import + `ruff` + `mypy` green.
- [ ] No test performs network I/O: the full suite is re-run with
  `socket.socket.connect`, `connect_ex`, `socket.create_connection` and
  `socket.getaddrinfo` patched to raise (throwaway pytest plugin, sanity-
  checked to fire) — must stay green. Every adapter takes an injectable
  `urlopen`; the converter is the scripted `FakeConverter`.

## 2. Behaviour checklist (maps to ROADMAP acceptance + locked decisions)

- [ ] Portrait passes the gate → success line + Q1 → answers × 5 → dossier
  report sent + stored (`done`) → **in the same update, no user input**:
  teaser → portrait `sendPhoto` with the generated bytes → `portrait_sent`.
  *Evidence: `test_converter_flow.py` component test asserts the exact send
  sequence and the final session state.*
- [ ] The request to Gemini 3.1 Flash Image is **pure multimodal**: exactly
  one `user` content whose parts are the original photo bytes (`inline_data`,
  base64) + the directive citing the dossier's `suggested_animal` and
  `summary`; persona only in `systemInstruction`; `responseModalities:
  ["IMAGE"]`; no intermediate text step, no `responseSchema`.
  *Evidence: `test_converter.py` request-body assertions (photo base64 equals
  the input bytes; directive contains animal + summary; one content;
  `systemInstruction`; `generationConfig`).*
- [ ] The returned image is validated before send: non-empty, `image/*`,
  ≤ `MAX_PHOTO_BYTES`; anything else is a `ConverterError`.
  *Evidence: `test_converter.py` unusable-output tests.*
- [ ] The portrait is delivered via multipart `sendPhoto` with the tiny
  caption, and the original photo is **never** sent to Telegram.
  *Evidence: transport multipart tests + component send-sequence assertions
  (only `sendPhoto`, no `sendMessage` echoing the raw image, no re-download).*
- [ ] Degraded conversion (hybridize failure, upload failure) → apology,
  loud `conversion_failed` log, **no** `portrait_sent`; the next update
  retries and completes.
  *Evidence: `test_converter.py` degradation tests + component degraded
  variant (`conversion_failed` event, flag still False, next update delivers).*
- [ ] A `done` chat missing photo/dossier fails loud and resets+re-prompts;
  never a crash.
- [ ] After `portrait_sent`, non-command input gets the light "observation
  complete" reply; no state change, no re-conversion.
  *Evidence: bouncer dispatch tests (`done && portrait_sent` delegates to the
  Interviewer's light reply) + component test.*
- [ ] `/start` / `/restart` mid-anything resets everything (photo, interview,
  dossier **and** `portrait_sent`).
  *Evidence: `test_session.py` reset test + bouncer reset test.*

## 3. Contract & safety checks

- [ ] `chat_id` stays `int`; `SESSION_VERSION` bumped to 3; `portrait_sent` is
  stored, typed state (never inferred).
- [ ] The generated image crosses every boundary as typed data (`GeneratedImage`
  / `InlineImagePayload` / typed `send_photo`), never a raw payload.
- [ ] Single redaction implementations survive: the API key never appears in
  any raised `ConverterError`/`GeminiError` message or log line; the bot token
  never appears in any raised `TelegramApiError` from `sendPhoto` (plain +
  escaped/control-character forms covered by the sweeps in `test_converter.py`
  and `test_transport.py`).
- [ ] Session, photo, dossier and portrait are isolated per `chat_id`.
- [ ] `TELEGRAM_BOT_TOKEN` / `GEMINI_API_KEY` never appear in logs; `.env`
  remains gitignored/untracked; no user photo bytes, base64 payloads or dossier
  text in logs (`portrait_sent`/`conversion_*` events carry only ids and
  sizes/mime).
